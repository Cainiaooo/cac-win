## 全局策略决策（在开 T01 之前必须确认）

1. **版本号策略**：T01–T06 的 PR **不修改** `package.json` 与 `CAC_VERSION`，所有版本元数据对齐统一在 T07 处理。原因是 fork 当前 `package.json=1.0.0`、`CAC_VERSION=1.5.8` 已不一致，每个 PR 各自 bump 会产生连锁冲突。

4. **Windows 专有内容保护**：任何 PR 都不得删除 `AGENTS.md`、`CLAUDE.md`、`scripts/install-local-win.ps1`、`tests/test-cmd-entry.sh`、`tests/test-windows.sh`、`tests/test-claude-autoupdate.sh`、`docs/windows/*`、`cac.cmd`、`cac.ps1` 中已有的 Windows 适配逻辑。

## 为什么不能直接 merge

`git diff master..upstream/master` 会显示上游删除或覆盖大量 Windows fork 专有内容（见上一节第 4 条）。`git merge-tree $(git merge-base master upstream/master) master upstream/master` 显示直接合并会在以下文件产生核心冲突：

- `cac`
- `src/utils.sh`
- `src/cmd_check.sh`
- `src/cmd_env.sh`
- `src/cmd_help.sh`
- `src/cmd_relay.sh`
- `src/templates.sh`

其中 `cac` 是生成文件，不应手工解冲突。正确做法是移植 `src/` 补丁后运行 `bash build.sh` 重新生成。

## Worktree 与 PR 规则

所有合入任务都按以下固定流程执行：

```bash
git checkout master
git pull origin master
git fetch upstream --prune --tags
git worktree add ../cac-win-wt-TNN -b merge/upstream-TNN-topic master
cd ../cac-win-wt-TNN
```

每个 worktree 只做一个小主题。优先手工移植或 `git show <commit> -- <paths> | git apply -3`，不要直接 `git merge upstream/master`。如使用 `git cherry-pick -n <commit>`，只保留本任务相关变更，并还原无关上游文件。

每个 PR 必须：

- 只修改本任务范围内的 `src/`、测试、文档和生成文件 `cac`
- 不修改 `package.json` 与 `CAC_VERSION`（统一在 T07 处理）
- 每次改 `src/` 后运行 `bash build.sh`
- 提交生成后的 `cac`、`relay.js`、`fingerprint-hook.js`、`cac-dns-guard.js` 中实际发生变化的文件
- PR 描述写明移植的上游提交（精确到 hunk）、Windows 适配点、验证命令
- CI 全绿后才能合入；合入前再次确认没有删除 Windows 专有文件

基础验证命令：

```bash
bash build.sh
shellcheck -s bash -S warning src/utils.sh src/cmd_*.sh src/dns_block.sh src/mtls.sh src/templates.sh src/main.sh build.sh
node --check src/relay.js
node --check src/fingerprint-hook.js
bash tests/test-cmd-entry.sh
bash tests/test-windows.sh
```

## 回滚策略

由于每个任务是独立 PR，回滚原则如下：

- 单个 PR 出问题：在 master 上 `git revert -m 1 <merge-commit-sha>`，不要走 `git reset --hard`。
- 多个 PR 链式出问题：按合入逆序逐个 revert，每次 revert 后跑一遍验证命令。
- 不允许在已合入的 PR 上 force-push 修复，必须开新 PR 修正。
